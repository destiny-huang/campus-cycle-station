# 需求基线 v0.2

## 1. 已确认：定位与角色
面向真实校内学生的公益闲置物品赠与系统；没有现金交易、借用和归还。
学校提供一个专用教室，分A小件100格、B中件50格、C大件20格，数量暂定、可配置。
学生姓名+学号登录，姓名与学号匹配已导入名单，不额外增加激活码或强验证。
教师统一导入姓名、学号、班级。一个教师端、一套权限、一位兼职教师即可管理；不建多级审批。
普通学生初始积分20，一人一份只发一次；教师可按姓名搜索，并通过班级/学号区分同名者，发劳动积分并记原因。
演示账号6个，每人初始总余额200；含一个教师演示账号；已有演示账号不因登录/重启/更新/重复seed重置。
fixtures/demo-students.csv都是虚构资料。演示数据与正式数据库/上传位置隔离，默认只在显式demo模式加载。
未实际投放的样例不得进入正式可领取库存；真实物品需正式投放与审核。演示与生产迁移方式不自动推定。
教师仍有简单登录口令，由运行环境配置，不在源码写真实口令，不要求学生增加密码。

## 2. 已确认：捐赠、审核、积分
每次仅提交一件；一套不可拆分领取的棋具/材料包可算一件。提交后有“继续捐赠”。
上传真实照片，提示背景干净；填写类别、名称、尺寸档/尺寸及基本状态；系统自动预留合适柜位。
学生按提示放入教室隔间，教师核实实物并审核后，积分到账、物品上架。
AI依据类别标准积分和成色给建议、解释及待核验项；教师可改最终分值。
基准分见config/points-template.example.json，属建议模板，可后台调整，不与人民币兑换。
积分须是整数；照片看不出的缺页/配件状态不得被AI断言为已验证。
审核已通过的计分应保存当时模板版本、AI建议及教师最终分值，模板改动不追改历史。

## 3. 已确认：柜位与领取
ABC分别维护持久化空柜FIFO队列：分配从队首取，核销后立即放回同类队尾。
队列不是一次性内存数组；重启保持顺序；多个申请并发不能拿到相同有效柜位。
同类型无空柜时提示不能入柜，不暗中超卖或分配过小隔间。柜体尺寸未测量，禁止凭类别名称保证适配。
教师可看每个柜位、物品与状态，处理位置异常；学生不需要等待教师手动选柜。
领取确认成功即扣分、核销、释放柜位，不再要求学生确认取走，也不等教师批准或巡柜。
同一事务保障：余额充足、物品仍可领取、扣分/流水/核销/释放全成功或全不发生。
已核销物品不可被第二人领取；积分不足不改变任何物品/柜位状态。
保留领取时的柜位和照片快照，旧领取记录不能跟随新入柜物品改变。
FIFO仅减少刚释放柜位立即复用，不保证实物已取走；保留“柜位异常”反馈，教师人工处理。

## 4. 流程状态（实现建议，不能删掉已确认的业务节点）
捐赠草稿→柜位预留/待投放→学生标记已投放/待审核→教师审核通过/可领取→已领取核销。
待投放可取消；已投放退回与普通取消不同：实物仍在柜中时不得悄悄释放，保留待退回记录。
异常、下架、退回可由教师处理；改变积分用补偿流水，不直接抹去历史。
取消时限、退款规则待定；未决时不自动清柜、不无限默认退款，可先留教师人工处理入口。
历史位置、当前有效占用、柜位可分配状态分别记录，避免核销即释放与历史记录混在一起。

## 5. 图片与AI展示
原图保留；后台提取主体、卡通化，展示页按真实柜位显示卡通物品。
轻量二维柜墙，桌面悬停小跳跃，移动端点击等价；动画不触发AI调用。
点击看真实照片、积分及领取入口；卡通图不可替代实物状况说明。
审核/积分、图片生成分别管理状态：图片失败不阻塞人工审核与领取，原图/占位图降级显示。
一次处理后持久化缓存，只有相关输入变化或明确重试才再调用；AI回调与重试不能重复发分。
不在共用服务器本地跑大型视觉模型。真实服务商、可用接口、模型、预算待选，先做明确标注的模拟适配器。
AI看不到全校学生名单/账号密钥；照片中的个人信息尽量裁去，上传使用大小/格式限制。

## 6. 工程约束
独立仓库、本地目录、服务器服务账号/目录/端口/数据路径/环境变量。
先本地实现与验收，后只读核查服务器，再由用户批准单独部署；不改动quiz代码/数据库/运行时/Runner。
不把任何猜测端口、进程名、服务器凭据写成既定事实。
所有代码、迁移脚本和演示seed需幂等，禁止启动时清库/重置余额/覆盖上传。
后台保留基础权限检查与事务正确性，不额外扩大账号安全产品范围。

## 7. 建议技术起点（M1检查后锁定，不是已有工程事实）
React + TypeScript + Vite；Node.js轻量API（可用Express）；独立SQLite；一个仓库。
生产尽量同域/一个Web服务对外，开发用代理；具体依赖与驱动需核对本机及生产兼容性。
先不用Redis、微服务、额外任务平台、3D引擎和本地大模型；任务队列可用数据库轻量实现。
不为了统一版本升级quiz的系统Node。性能是否充足由后续测量判断。

## 8. 尚未单独确认，不能误写成用户定案
- 捐赠奖励与领取价格相等：建议默认相等，设置允许调整；不做动态涨价。
- 各类别具体基准分和成色系数：模板是试运行建议，教师可调整。
- 柜位实际尺寸、各类允许物品、投放预留期限和异常退款细则。
- 正式AI服务商、单日费用上限、上线域名/路径/端口与服务器资源预算。
以上不阻塞M0/M1。进入相关阶段再确定；不能由Agent偷偷开启付费服务或生产清理任务。

# M1.1 视觉规范：第二套 · 简约卡通校园风

## 0. 目标与边界
在现有 React/TypeScript/Vite 的 M1 上做 UI 改版，不重建应用。
三端仍为 /student、/teacher、/locker-wall；原 API、SQLite、健康检查不变。
参考同目录 references 中三张图的卡通氛围和木柜结构，不复制照片写实版或第一/第三套。
用户选定：活泼但简约、少圆角、卡通实木柜和很多隔板。不是再出三套方案。
仅表示视觉选择已定，不表示参考图中的业务功能已经实现。

## 1. 全局视觉
- 底色以暖白为主，深绿文字和主操作，木色用于柜体，浅蓝/浅绿只做小面积点缀。
- 大容器尽量不画包围框，先用留白、分隔线和文字层级分区。必要容器/按钮/输入框圆角 0–4px；不要胶囊按钮、24px大圆角卡片和卡片套卡片。
- 保留手绘插画气质，但不把页面做成幼儿园海报。系统标题/正文使用已有可用中文字体，不下载大型字体库。标题约28–36px，正文14–16px；不再用占据半屏的大字。
- 导航约64–72px高，只有学生端、教师端、柜位展示三个入口，选中项用下划线或小面积浅色提示。
- 桌面内容宽约1200–1320px，间距16–24px；手机留白12–16px。尽量在首屏看到主要操作。
- 校园插画只留一条低矮、低干扰的装饰区。学生端不高于约160px、教师端只保留小标题区、柜墙不高于约100px。
- 装饰限制：不要四角满铺树叶、重复标语、浮动吉祥物、公告大栏和各种无关统计。不用宣传横幅挤压教师操作区。
- 木头可有层次/阴影，普通页面不堆玻璃、发光、渐变大色块或大投影。
- 圆形金币、叶片和状态点属于插画元素，不必强行做成方形；少圆角针对页面容器。

## 2. 学生端 /student
目标：一眼找到积分和三个主要入口，而不是阅读宣传页。
首屏：简短问候 + 小型校园插画 + 当前积分区。
主操作：捐赠物品 / 浏览物品 / 我的记录，以清晰图标和短文案构成，不用三块巨大圆角卡片。
下方：约4件物品预览，有图、名称、积分、柜位；不设未经实现的“AI个性化推荐”。
M1.1 使用独立只读演示数据：页面明显写“界面演示，尚未接入业务”。可显示“示例账户 · 200积分”。
未来普通学生初始20，测试学生200；不能把图中120分写成新业务规则。
未实现的捐赠/领取等操作显示待开发提示，不弹“成功”、不改变余额、不写入本地存储假冒后端。
可实现前端导航、筛选演示物品、打开示例详情；详情写明不是真实库存。
不新增注册入口、验证码、激活流程；业务方案仍是姓名+学号登录。

## 3. 教师端 /teacher
统一一个轻量教师端；保留同套绿/木色、线描图标，但装饰比学生端少。
顶部用短标题“循环站管理”，配一行简洁的演示概览；没有数据就“—”，或所有数字明确来自演示fixture。
主体左侧：待审核列表，能看清物品、示例学生姓名/班级、柜位、建议分、最终分位置。
主体右侧：按姓名/学号搜索学生与劳动加分位置；下方紧凑显示ABC柜位概览。
第一轮只呈现可接入的视觉骨架。审核/加分按钮必须标注待开发或禁用，不能提交假成功。
不增加权限级别/多教师协作/公告运营/多重统计面板；不展示无依据的减碳公斤数、植树数或增长百分比。
示例学生统一初一/初二/初三班级，不使用图中的大学、学院、大学教材信息。

## 4. 柜位展示 /locker-wall —— 本次最重要部分
视觉必须是三组“由木板搭出的卡通实木柜”，不是棕色卡片阵列。
柜体要看得出：厚实外框、顶板、左右侧板、内侧阴影、低对比木纹背板、连续横隔板、竖隔板、底座。
格子之间是共享木板，没有圆角卡片之间的悬浮间隙。每格正面下沿有清楚的编号纸签。
A/B/C放在柜体上方的小木牌上；A小件100格，B中件50格，C大件20格，共170格。
A格最密，B中等，C最宽大；保持物品落在隔板上的视觉，不漂在格子正中央。
编号是数据生成的文字，不烘焙进图片、不重复编号：例如A01…A99、A100。
柜体、格位、编号、物品、状态均应分层；物品使用独立图片/简单本地示例素材，与柜体分开。
图片不可用时有不会撑坏柜子的占位；外观素材可用已有本地资源、SVG/CSS模块组合，不引入3D库。
完整参考图只用来对照，不做网页背景或整页图片点击热区。

### 展示规模
170格不挤进一个首屏。桌面三组柜子同时展示，各自有页码/编号范围。
建议每板：A 5列×4行=20格；B 4列×3行=12格；C 2列×2行=4格。
A共5板，B共5板（末板仅B49、B50为有效格），C共5板。少量空白填充不是新增柜位。
这是“展示板分页”，不是线下新增柜子；不能改变实际柜位编号或FIFO。
示例柜位配置在一个文件生成，所有编号覆盖A100/B50/C20；统计与样例数据计算一致。
说明“展示设计样例，非实时库存”。不用假装已有真实队列分配功能。
手机切换A/B/C单组柜体，保留分页和可读编号；桌面变窄时也可切换单组，不压成170个小点。

### 状态与互动
使用小标识/纸签+文字表达空闲、已预留、待审核、可领取、停用等未来状态，不大面积涂满每一格。
“已领取”保留在未来历史记录，不在当前柜位上增加“待取走/确认归还/等待腾空”流程。
学生取用成功立即核销、释放入对应FIFO队尾，这是业务不变项。
有示例物品的格子悬停或键盘聚焦时，物品轻跳一次（建议4–6px、约240ms）；柜体和编号不跳。
按减少动态效果偏好取消位移动画；手机点按看详情，不依赖hover才能操作。
点击打开“示例物品详情”侧栏/弹层，可关闭；点击遮罩和Esc可关闭，焦点能回到原格位。
不自动循环跳动，不每格同时播放动画，不在浏览/悬停时调用AI。

## 5. 参考图不能照搬的内容
- 2025版权日期、大学/学院信息、图中不连续编号、不同总格数和积分数不作为开发依据。
- 不保留“免费领取”误导：真实领取消耗积分；捐赠经投放和教师审核才加分。
- 无依据的减碳/植树估算全部删除；没有公告需求，不新增公告系统。
- 图里的猫若保留只能是柜外装饰，不是可捐赠/可领取的活体物品；省略更好。
- 物品展示优先课外书、文具盒、尺子、手工材料、篮球、书包，积分可取项目既有标准模板。
- 标题/说明/编号/积分用真实DOM文字，便于修改与接入数据。

## 6. 工程与验收
沿用现有工程和依赖；优先复用UI组件/样式，不重装框架，不改锁文件解决外观问题。
后端接口、SQLite schema和数据不修改；如视觉功能需要新业务接口，记录为M2以后事项。
只读演示fixtures与业务数据分离，不执行seed、清库或造假接口。
本地设计参考图不放public，不在运行时加载整张截图；无需新增图像生成API。
保留已有API健康检查、数据库检查和开发/构建命令。
运行 npm.cmd run typecheck 与 npm.cmd run build，实际启动核查原健康接口。
可用浏览器工具时验证1440×900与390×844下三端，检查导航/刷新/溢出/柜体比例/弹层/控制台并留截图。
没有浏览器工具就报告“视觉未验证”，不要用HTTP200代替视觉验收，也不自行安装新插件。
用短清单对照：少圆角、确有木板隔断、柜格大小层级、完整170编号可访问、手机可读、数据标为示例。
完成后更新docs/progress.md，保持M2未开始；不提交/推送/部署。
